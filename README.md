# Зерно — магазин кофе

## Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Проект сделан на основе HTML/CSS-сайта из КР №1 (без Bootstrap). Сайт адаптирован под телефоны, планшеты и компьютеры, а также проверен на доступность.

## Адаптивные решения

- добавлен файл `css/responsive.css` и подключён на всех страницах;
- на всех страницах есть `<meta name="viewport" content="width=device-width, initial-scale=1.0">`;
- применён подход **Mobile First**: сначала написаны стили для телефона (всё в одну колонку), потом через `@media (min-width: ...)` добавляются колонки для больших экранов;
- из `style.css` убраны фиксированные колонки и ширины (например, `width: 400px` у модального окна), из-за которых сайт ломался на телефоне.

Точки перелома:

| Ширина | Что меняется |
|---|---|
| до 575px | всё в одну колонку, меню скрыто за кнопкой «Меню», таблица сравнения в виде карточек |
| от 576px | карточки товаров в 2 колонки, кнопки товара в строку, таблица сравнения снова таблица |
| от 768px | меню в строку, hero в 2 колонки, фильтр каталога — боковая колонка, страница товара в 2 колонки, форма заявки в 2 колонки, контакты и форма рядом |
| от 1024px | карточки товаров в 3 колонки, крупнее заголовок hero |
| от 1440px | контейнер шире (1240px), ещё крупнее заголовок hero |

Что адаптировано:

- **Навигация** — на телефоне меню скрыто, открывается кнопкой «Меню» (кнопка меняет `aria-expanded`), закрывается по Escape. С 768px кнопка пропадает, меню в строку (Flexbox).
- **Hero-блок** — на телефоне текст и картинка друг под другом, кнопка на всю ширину; с 768px две колонки (Grid).
- **Сетка карточек** — CSS Grid: 1 → 2 → 3 колонки. Карточки сделаны через Flexbox, чтобы кнопка «Подробнее» всегда была внизу карточки и кнопки стояли на одной линии.
- **Каталог и фильтр** — на телефоне фильтр стоит над товарами, категории показаны «таблетками» в строку (Flexbox с `flex-wrap`). С 768px фильтр становится боковой колонкой и прилипает при прокрутке (`position: sticky`).
- **Страница товара** — 1 колонка на телефоне, 2 колонки с 768px.
- **Таблицы** — обёрнуты в `.table-wrapper` с `overflow-x: auto`, поэтому прокручивается только таблица, а не вся страница. Таблица сравнения сортов на телефоне показывается **карточками**: каждая строка — отдельная карточка, а название столбца берётся из атрибута `data-label` через `td::before`.
- **Формы** — на телефоне одна колонка, поля высотой не меньше 44px, кнопка на всю ширину. С 768px форма заявки в две колонки (Grid), комментарий и кнопка на всю ширину.
- **Контакты** — добавлена форма обратной связи. На телефоне контакты и форма друг под другом, с 768px рядом.
- **Подвал** — на телефоне элементы в столбик по центру, с 768px в строку. Добавлен отступ под кнопку «Наверх», чтобы она не закрывала ссылки.
- **Модальное окно** — ширина `100%` с `max-width: 400px`, поэтому на телефоне не вылезает за экран.
- Добавлены `overflow-wrap: break-word` для длинных слов и `scroll-padding-top`, чтобы при переходе по якорю блок не прятался под липкой шапкой.

## Responsive images

- в `responsive.css` есть правило `img, video { max-width: 100%; height: auto; }`;
- **srcset и sizes** — у карточек товаров есть картинки 400px и 800px, браузер сам выбирает нужную в зависимости от ширины экрана и плотности пикселей;
- **picture + WebP** — на странице товара картинка отдаётся в формате WebP (он легче), а если браузер его не поддерживает — в JPG;
- **picture с разными картинками** — в hero на телефоне показывается обрезанная картинка (чашка крупнее), а с 768px — полная;
- у картинок указаны `width` и `height`, чтобы страница не прыгала при загрузке, у картинок ниже первого экрана — `loading="lazy"`.

Проверить можно во вкладке Network в DevTools: на ширине 360px загружается `hero-mobile.webp`, на 1440px — `hero.webp`.

## Доступность

- добавлена ссылка «Перейти к содержимому» (skip-link), она появляется при первом нажатии Tab;
- видимый фокус (`:focus-visible`) у всех ссылок, кнопок и полей; в подвале рамка фокуса белая, потому что коричневая на тёмном фоне не видна;
- у всех полей форм есть `label`, у чекбоксов фильтра — `fieldset` и `legend`;
- у всех изображений осмысленные `alt`;
- на каждой странице один `h1`, заголовки идут по порядку;
- навигация размечена через `nav`, у двух меню разные подписи (`aria-label="Главное меню"` и `"Нижнее меню"`), у текущей страницы `aria-current="page"`;
- у кнопок «Подробнее» добавлен скрытый текст для скринридера («Подробнее о товаре «Эфиопия»»), иначе все кнопки звучат одинаково;
- у кнопки «Наверх» и крестика модального окна добавлен `aria-label`, потому что там только символ;
- модальное окно: `role="dialog"`, `aria-modal`, `aria-labelledby`, закрывается по Escape, после закрытия страница возвращается к кнопке «Оставить заявку» (ссылка `#buy`), а не прыгает наверх;
- исправлен контраст рамок у полей формы (было `#e5d6c6` — почти не видно на белом, стало `#9c8573`);
- у полей добавлен `autocomplete`, чтобы на телефоне было удобнее заполнять;
- ARIA используется только там, где без неё не обойтись.

## Lighthouse

Проверка делалась на опубликованной версии сайта (GitHub Pages) в Lighthouse 12, режим Mobile, категория Accessibility.

| Страница | Accessibility |
|---|---|
| `index.html` | 100 |
| `catalog.html` | 100 |
| `order.html` | 100 |
| `product.html` | 100 |
| `contacts.html` | 100 |

Отчёты сохранены в папке `lighthouse/`:

- `accessibility-report.png` — скриншот результатов для `index.html`, `catalog.html` и `order.html`;
- `accessibility-index.html`, `accessibility-catalog.html`, `accessibility-order.html` — полные отчёты, их можно открыть в браузере.

Lighthouse проверяет не всё (например, удобство работы с клавиатуры и понятность текста он сам не оценит), поэтому меню, модальное окно, skip-link и порядок фокуса я дополнительно проверил вручную клавишей Tab.

## Самостоятельные доработки

- мобильное меню с кнопкой, `aria-expanded` и закрытием по Escape;
- фильтр каталога в виде «таблеток» на телефоне и липкая боковая колонка на компьютере;
- кнопки в карточках выровнены по низу;
- таблица сравнения сортов превращается в карточки на телефоне;
- несколько вариантов responsive images: `srcset`/`sizes`, WebP через `picture`, разные картинки hero для телефона и компьютера;
- форма обратной связи на странице контактов;
- skip-link, доступное модальное окно, скрытый текст у кнопок «Подробнее», улучшенный контраст полей.
